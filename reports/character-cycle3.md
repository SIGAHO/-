# キャラクター対話・再生成追試（2026-10-30）

前回の実験後、通常の書き直しと、壊れた初稿を渡さず実際の会話文脈から再生成する実験を比較した。別Codexによる非盲検レビューはreferenceが2/6、repairが1/6ターン合格で、両セッション不合格。初稿も異なっており、再生成方式だけが初稿の違いを生んだとは言えない。全会話品質は未達であり、新方式を本番の既定へ採用しない。

repairの初回には英語の内部指示や壊れた日本語が混じり、再生成も英語の内部指示とユーザー入力の反復を含んだ。既存選択器はどちらも不適切なのに初稿をfail-openで配信し、次ターンのassistant-role履歴にも残した。ユーザー発言・State/Verified Memoryへの昇格とは区別して、会話履歴への汚染を確認した。原文と要求全文はreports/live-profiles/cycle3-referenceとcycle3-repairに保存。

このケースへの実験的対処として、character-repairだけで両候補とも言語混在が検出された場合に、壊れた文ではなく固定の失敗通知を返し、Provenanceでその出所を示す方式を実装した。これは自然な会話の成功ではなく、検査を逃す破綻には効果がない。legacyの既定fail-openは変えていない。FakeModelAdapterのテストは通知・履歴・出所の接続確認であり、実会話品質評価ではない。

さらにguardの実Qwen会話では日本語と中国語を句読点や引用で混在させた破綻が検査をすり抜けた。引用を保護したうえで中国語の読点でも分割し、観測した例に回帰テストを追加した。guard2の再検証は最初の生成要求でOllama HTTP 500となり、返答を得られなかった。新しい検査・失敗通知の実Qwen再評価は未達。Ollamaのモデル一覧上はロード済み、GPU空き401MiBだったがHTTP 500の原因とは断定できない。サーバの再起動や既存データの変更はしていない。

当該実験の要求上限は60回、1回60秒、同時1、通信失敗時の自動retryなし。条件ごとのraw payloadと結果、FIO・イベントは新規隔離profileに保管。未承認の架空例を使い、人間承認や学習データとして扱わない。修正後の自然さ・日本語維持・再起動後の対話を新規実モデル会話で評価する必要がある。詳細な独立採点はcharacter-cycle3-independent.md。

unit 491件とBehavior 107件は全件通過（cycle3-unit.log、cycle3-behavior.log）。全unit開始後に追加した空の書き直しの分岐とProvenance説明については関連テストを別途実行したが、全suiteはその後再実行していない。結果は機械的な回帰検証であり、実Qwenの会話合格ではない。
