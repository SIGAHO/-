## 1. [P1] 他人の別タスクの完了で、自分の未完了事項が消える

対象：src/companion_core/open_loops.py の observe / _auto_close、src/companion_core/core.py の _observe_user / Replay。

再現手順：

1. 分離した一時ログでCompanionCoreを作る。
2. `あとで宿題を提出する` をhandleする。activeな未完了事項が1件できる。
3. `友達が書類を提出した` をhandleする。
4. activeが0件になり、自分の宿題が完了扱いになる。
5. 同じ一時ログでCompanionCoreを再起動してもactiveは0件のまま。

2文の文字bigram類似度は0.222222。_auto_closeは0.18以上で一意の候補なら完了にする。行為者や対象の一致を確認しないため、共通の提出動詞だけで別の作業を閉じられる。`あとでレポートを提出する → 友達がレポートを提出した` でも同じ誤完了を確認した。

修正範囲：類似度は候補の検索に留め、明示的な別行為者や異なる対象では自動完了させない。確定できない入力では元タスクを維持する。既存の「単独の未完了事項に対する終わった」は、曖昧性を解決できる既存条件を保って検証する。

## 2. [P1] 助言の拒否を、CPUが助言の依頼へ反転する

対象：src/companion_core/alignment.py の Acts.rejection / PolicyPlanner.observe / plan。

再現手順：

1. 直近履歴としてユーザー `今日は眠い`、assistant `寝た方がいいよ。` を用意する。
2. ユーザー `方法は聞いてない。ただ眠いと言っただけ` をobserveしてplanする。
3. 実測はreaction_to_previous=unknown、explicit_feedback=None、response act=advise、advice_allowed=True。

追加の再現文：

- `手順は求めていない。話を聞いて` → advise / advice_allowed=True。
- `アドバイスは要らん` → advise / advice_allowed=True。
- 逆方向では `やり方を教えてほしい` → continue / advice_allowed=False。

原因：requested_adviceは `方法|手順|アドバイス` などの単語の存在だけで真になる。拒否側は `求めてない` といった一部の形だけを認識し、`求めていない`、`聞いてない`、`要らん` を拾わない。否定の範囲や発話の目的が一致していない。結果としてQwenに渡す制御信号自体がユーザーの意思と逆になる。

これはユーザーの中核の希望である「求めていない助言を追加しない」をCPUが破る不具合。禁止語検査を出力へ追加するだけでなく、依頼と拒否の判定を同じ対象行為について整合させる必要がある。一般的な自然言語理解の全面改修を行う必要はなく、まず観測した否定例と対応する肯定依頼例を明示的に分離できる範囲を修正する。

必要な回帰：上の拒否3件は助言不許可、実履歴がある場合は適切な拒否feedbackとして扱う。一方、`方法を教えて`、`手順が知りたい`、`やり方を教えてほしい` は助言依頼として許可する。引用中の依頼語や、否定の反転を含む曖昧な文を単語だけで断定しない。モデルの自然さとは別にCPU制御として検証する。

## 4. [P2] 分を省略した正時の差を、CPUが計算できない

対象：src/companion_core/intent.py の time_request、src/companion_core/cpu_answer.py の answer。

固定の実行時刻を2026-10-30 08:00 Asia/Tokyoとして再現：

- `9時00分から10時00分まで何分？` → 同じ経路で60分。

原因：時刻差pairの正規表現が両端の時の後に分の数字を必須にしている。曖昧性のない正時の省略にも0分を補えない。CPUで確定できる時刻計算を行うという設計に対して、表記上の欠落で失敗している。少なくとも正時の省略はモデルを呼ばず処理できる。

修正範囲：両端それぞれの省略分を0とするパーサー。既存の0〜23時／0〜59分の検証と日跨ぎの既定条件は維持する。必要な回帰は両端正時、片端だけ分あり、既存の分付き、境界の不正時刻。`半` は今回の必須修正に含めるか明示して別条件で試験する。
