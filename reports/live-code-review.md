# Independent code review — live dialogue experiment

Reviewer: separate Codex review agent, external assistant, not human and not Qwen. Read-only review of the working-tree diff against HEAD plus the new experiment driver and regression tests. Only this report was written. This is a correctness and preservation review, not a full security audit or a conversation-quality approval.

## Result

No blocking defect found in the reviewed change that destroys original data, enables an unvalidated prompt by default, fabricates human approval, or trains/exports experimental examples. Candidate quality remains failed under the separate live holdout review; this code review does not override that result. Keep all experimental modes opt-in.

## Evidence and boundaries

- `src/companion_core/chat.py`: the only change adds the keyword-only `prompt_mode` with default `legacy` and passes it to `PromptBuilder`. Existing callers retain their previous prompt mode. No event, memory, Replay, provenance, feedback approval or training persistence code is changed here.
- `src/companion_core/prompt.py`: default `legacy` construction follows the existing path. Experimental modes construct request-local strings and message dictionaries. The eight fictional example messages are returned to the adapter; they are never supplied to `CompanionCore.handle`, `EventStore.append`, MemoryEngine or FIOMemory as observed user events. Labels explicitly identify fictional/unapproved examples. Such examples may influence generated output, which is why transcript review remains necessary, but the construction does not directly insert them into user memory.
- `scripts/live_dialogue.py`: profile names reject separators and dot traversal; storage is selected under `reports/live-profiles/<name>/events.jsonl`. FIOMemory derives its sidecar paths from that same event path. Retrieval is explicitly disabled via `RetrievalEngine()`. Requests, responses, failures and dialogue rows are appended; old condition config must match before reuse. Existing personal logs are not selected by the script. No delete, reset, approval, training, model download or deployment operation appears in the driver.
- Real requests use the existing local Ollama endpoint with bounded prediction/context and a 60-second request timeout. An append-before-call ledger counts failures and rewrites. Maximum 100 attempts and a two-hour limit apply to this driver. Enforcement assumes the documented single concurrent request; the ledger is not a cross-process atomic reservation system.
- `src/companion_core/alignment.py`: two regex extensions recognize indirect refusal and explicit role negation. They change planner classification in default sessions too; this limited behavioral change is intentionally covered by the first two new tests. They do not approve a preference. Existing FIOMemory creates only pending candidates with `human_approved=False`, and the existing PreferenceStore requires a separate matching review before promotion. Synthetic driver feedback uses the existing user-event schema; its profile config and protocol must remain attached so no one mistakes assistant-operated scenarios for human endorsement.
- `tests/test_live_dialogue_regressions.py`: tests assert refusal recognition, role correction, default legacy behavior, and noninsertion of the fictional example into user events/memory. They are plumbing/control tests using FakeModelAdapter, not evidence of natural real-model replies. Existing expected values were not weakened in these four new tests.
- `scripts/generation_comparison.py`: deterministic UUID patch is confined to `prepare()` and its temporary fixture session. It returns small stable UUID values so an incidental random ID cannot contain the removed personal rank token. `uuid.UUID` itself remains real. Context-manager exit restores `uuid.uuid4` before actual inference; real model calls are not mocked. Existing fixture expectations are unchanged. This fix does not change the frozen prompt source used by the already completed holdout.

## Nonblocking observations

1. `new_process_replay=True` is written on every turn inside the driver loop even when multiple text arguments share one ChatSession in one invocation. It identifies a process that initially replays a profile, but does not prove a separate restart before every individual turn. Prefer an invocation ID/PID plus an explicit first-turn marker in a future diagnostics-only change. Current reports already limit this inference. This does not invalidate the reported separately invoked explicit recall, but exact process evidence is stronger than the flag alone.
2. Config identity binds mode and temperature but not prompt-source hash. A developer can reuse one development profile while editing the source and mix conditions. Per-turn prompt SHA and exact request payloads preserve detectability; the reviewed run uses distinct development names and a pre-holdout freeze. A future runner can reject hash changes within a profile instead of relying on discipline.
3. The broadened correction regex can classify a noncorrective phrase ending in `じゃない。` as a correction. This is a bounded semantic false-positive risk, not data corruption. Keep the rule modest and add actual observed counterexamples if this becomes a recurring problem; no unrelated classifier rewrite is requested.
4. The temporary process-wide UUID patch assumes fixture preparation has no concurrent UUID users. The current comparison driver is synchronous and its fixture is isolated. Avoid invoking `prepare()` concurrently with unrelated application sessions.

The reviewer inspected the diff, driver, tests, event-path derivation, EventStore initialization, FIOMemory recording path and existing human-review gate. A targeted local test rerun using the default Python could not import the package because `janome` was absent in that interpreter; no tests ran in that attempt. This is an environment limitation, not a passed test or a newly demonstrated product regression. The main operator's separately recorded regression results remain separate evidence, not an independently reproduced reviewer result.

No source, tests, original dialogue, memories or evaluation criteria were edited by this reviewer. Static review cannot prove historical preservation of every external file or validate every storage failure path. The live quality review and its unmet result remain authoritative for conversational readiness.
