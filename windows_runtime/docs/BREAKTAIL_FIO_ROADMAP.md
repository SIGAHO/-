# Breaktail 能力拡張ロードマップ

対象: このリポジトリの `windows_runtime/`。目的: 長期記憶、道具を使った作業、継続作業を、実測と出典で確認できる形にする。比較資料や論文に書かれた他エージェントの機能をBreaktailの実装済み機能と取り違えない。

## 進め方

1. この文書の最初の未完了項目から着手する。既存のコード、テスト、公開ドキュメントを確認する。
2. 関連する論文の一次資料を読み、採用する設計と限界を変更記録に明記する。
3. 小さく実装し、該当テストと回帰テスト、可能なら実会話で確認する。実行していない道具や未検証の結果を成功と呼ばない。
4. 完了条件を満たした項目だけチェックし、実測、残る問題、次の一手を追記する。

## 公開コードから確認できる現在地

- `breaktail_memory_hub.py` は同じ会話のRawを出典付きで参照する。一般的な意味検索やリンクを辿る記憶網は未実装。
- `breaktail_agent.py` は明示した作業場所でファイルを扱う。`breaktail_web.py` の通常会話経路とは分かれている。
- `/memories` は保存済み解釈記憶を一覧する。Raw、解釈Memory、プロフィール、作業結果は区別して扱う。
- 公開ドキュメントは自然な会話品質と完全な自律エージェントを未合格としている。

## M1: Webと実際の道具を接続

- [x] Webに通常会話と区別した明示的な作業経路を作る。利用者が対象フォルダーを指定する。最初は既存 `Workspace` の `list_files` と `read_file` のみ接続する。
- [x] 実行した道具、対象、観測結果、失敗を画面に表示する。未実行の操作を「調べた」と言わせない。
- [x] 権限外・保護領域・リンク・巨大ファイルの拒否をテストし、指定した作業場所で読取りを実演する。
- [ ] 編集、差分、構文検査、取消・再開は別段階で明示的に接続し、既存の保護と検証を保つ。

## M2: 記憶を出典でたどる

- [ ] Rawを正本とし、出典ID・時刻・発言者とともに提示する。記憶一覧は範囲、件数、ページ境界を明示する。
- [ ] 訂正前後を残し、最新の有効値の根拠を示す。未確認を確認済みに自動昇格させない。
- [ ] 必要な記憶だけを文脈に入れ、採用・除外理由を記録する。意味検索やリンク探索は既存経路との比較で有効性を測ってから採用する。
- [ ] 複数セッション、時間の前後、更新、根拠がない時の回答保留を評価する。

## M3: 作業の継続と振り返り

- [ ] 依頼、道具の観測、失敗、修正、検証を出典付きの追記記録にする。過去の検証を今回の成功と混同しない。
- [ ] 明示的な再開・取消をWebから利用できるようにし、二重実行を検証する。
- [ ] 入力がない時間の処理は読取りだけから試す。通知や外部操作は個別の接続と許可を前提にする。

## M4: 会話品質と速度

- [ ] 挨拶の反復、能力の虚偽申告、記憶一覧の拒否、訂正の取り違えを匿名化した回帰ケースにする。私的な会話原文はこのリポジトリに入れない。
- [ ] 正答率に加え出典の正しさを確認する。短文はモデル呼出し回数と各段階の時間を測る。
- [ ] 速度改善は記憶・安全・自然さの回帰がない場合だけ採用する。

## 2026-11-11 M1 進捗

- 公開ブランチに読取り専用の `/api/workspace/read` とWebの明示操作を追加。モデルの作文ではなく既存 `Workspace` の `list_files` / `read_file` の観測を表示する。結果には対象とSHA-256を含む。読取り結果は会話履歴へ混ぜない。
- 既存の作業場所検証を再利用し、書込み道具・相対パス逸脱・本体領域・64KB超を拒否した。Host/Originもローカルに限定した。リンク拒否のWeb経由検証は次の確認事項として残す。
- GitHubブランチの独立チェックアウトでWeb関連テスト8件成功。本番Webではファイル一覧と読取り、書込み・本体領域の拒否を確認し、保存済み会話件数が再起動前後で変わらないことを確認した。検証用の作業場所は公開用コピーを使用し、私的なファイル内容をGitHubへ送っていない。
- [ReAct](https://arxiv.org/html/2210.03629) の行動・観測・推論の分離を参照。今回は利用者の明示操作→実行→観測の最小ループを採用し、モデルによる自動道具選択はまだ有効化しない。論文自体も空振り検索や反復行動を失敗例として示している。
- [Toolformer](https://arxiv.org/html/2302.04761) の制限節を確認。道具の連鎖・対話的な再検索・入力表現への頑健性・呼出し費用は未解決の点として、将来の自動選択を評価する時の検査項目にする。論文の学習手法を現行モデルに導入したわけではない。
- 次の一手: Web経由でリンク拒否を検証し、選択した作業場所の一覧から読取りまでの操作性を改善する。その後、編集機能は明示承認・差分・バックアップの設計を確定してから接続する。

## 2026-11-11 M1 Web作業エージェントの実測

- 明示的な別画面から作業場所と依頼を指定し、最大8手・4分の作業をキューに登録できるようにした。状態、実際に実行した道具、観測、失敗、変更、実行IDを表示し、停止・チェックポイント再開・待機作業の再試行を用意した。通常会話は自動で道具を起動しない。Web経由のコード・テスト実行は無効にした。
- 読取りの拒否について、Web経由のテストで相対パス逸脱、保護領域、64KB超、Windowsジャンクションを確認した。独立チェックアウトでエージェント、キュー、Web、作業場所の計49テストが成功した。HTMLのJavaScript構文検査も成功した。
