# FIO資料を参考にした原文記憶ハブ

2026-11-09。FIO紹介資料の「全文を読み返す」「未確認を残す」「訂正を次回へ持ち越す」を、既存Breaktailの保存形式を変えずに取り入れた。

## 入った機能

`current/breaktail_memory_hub.py` が同じ会話IDの保存済みRawを読み直し、関連する過去の本人発言を出典ID・記録時刻と一緒に返答の入力へ渡す。Webと統合CLIが使う `build_reply_messages` に接続している。最近の5往復に入らなくなった発言も候補になる。

これは既存のMemory Gateが失敗した時の代替経路ではない。Memoryの解釈要約は従来どおりGateを通す。新経路は、原文をそのまま使う、本人発言だけの読み取り経路。本人申告は外部の確認済み事実として扱わない。AI自身の返答や提案は取り込まない。

`前に`、`以前`、`覚えて`、`続き`、`あの件`、`経緯`等の振り返りに関連する発言を文字列から検索する。一般的な意味検索や全件の常時注入ではない。出典の順に渡し、新しい訂正と今回の入力を優先する。

## 未確認・未完了の明示メモ

普通の会話の一行として次のように送る。コマンド登録や外部実行ではない。

```text
未確認：望遠鏡修理｜交換部品の在庫を確認する必要がある
未完了：引越しの荷造り
確認済み：望遠鏡修理
完了：引越しの荷造り
取消：引越しの荷造り
```

`｜`より前を同じ項目名として照合する。`未確認`・`未完了`・`保留`が残り、同じ項目名の`確認済み`・`完了`・`取消`・`取り消し`で閉じる。現在の完了発言も、その返答から反映する。引用・質問・例文から勝手に仕事を作らない。自然文から任意の予定を推測して登録する機能ではない。

未完了の項目は無関係な雑談の時も最大3件まで入力側へ持ち越すが、毎回催促したり勝手に調査・予約を実行したりしない。通知・電話・時刻指定実行・自律推論は追加していない。「確認済み」は本人が伝えた状態であり、Breaktailが外部確認したという証拠ではない。

実会話で、閉じた項目をモデルが未確認のまま復活させる例があったため、同名項目の最新状態を原文で照合する。単独の状態質問には、その申告と出典から状態だけを確定して答える。窓口・金額・理由等も併せて尋ねる質問は、この状態文だけで丸ごと置換しない。返答の書き直しでも採用済み原文を文脈予算内で引き継ぐ。

## 保全・制限

- Raw/Memory/プロフィール/教師データ/モデル重みの形式変更や移行は不要。新しい保存DBは作らない。既存Rawを読み直すだけなので安全モードでも利用できる。
- 同一会話IDに限定。別会話の記憶の自動共有はしない。会話IDが無い呼び出しでは使わない。
- 生成途中・失敗・未コミットの統合CLIデータ、ロールプレイの場面記録は除外する。現在の入力を自分自身の根拠にしない。
- 読み取り上限はRaw末尾4MiB、最大2000行。引用は一件1000文字以内、合計2600文字以内。長い原文を途中で切らず、その候補を外す。
- 現在の会話入力と履歴の文脈予算を優先。余裕がなければハブの追加分を外す。
- 不正な原文や読めない台帳を見つけたら根拠を入れずTraceに理由を残す。読めなかったことを「過去に話していない」と言い換えない。
- Traceの `raw_memory_hub` に採用出典、未完了項目、読み取り上限の適用、非採用理由を記録する。
- `BREAKTAIL_RAW_HUB=0` を起動プロセスに指定すると新しい原文参照を停止できる。既存のMemory Gateはそのまま使う。省略時は有効。

## 検証

新規テストは古い会話の参照、別会話の隔離、訂正の順序、未完了の解除、引用内命令のデータ扱い、未コミット除外、原文破損、文脈予算などを検証する。既存の回帰テストと実際のローカルモデルの会話は別に記録し、テスト通過を自然な日本語や全機能の合格とは扱わない。実会話の原文はローカル評価出力に保存する。

最終版は既存を含む358件と部品9件、計367件が成功（新規24件を含む）。17往復の実会話および同じ履歴から機能を無効にした比較1応答を確認した。古い窓口訂正・見積もり・未予約の再現、未確認内容の追質問、窓口の変更経緯、確認済みの状態照合は確認できた。一方、複数質問の回答漏れ、雑談中の不要な推測、挨拶が「うん。」になる例は残る。原文検索の成功は、返答品質全体の合格ではない。
