# 記憶を次の判断に使うための開発方針

利用者の要望は「記憶で賢くなること」。単なる会話ログの保存に留めず、訂正・作業結果・失敗を次の判断へ戻す。

## 実装済みの範囲

会話のRaw記録と訂正の保持、および作業エージェントのプロジェクト内の過去記録の読み戻し。
作業は関連する前回の依頼、変更したファイル、失敗した道具、検証の結果を最大3件参照する。
前回のファイル内容と現在の内容が同じかをハッシュで確認し、利用した記憶の出典を残す。
現在の依頼と現在のファイルを優先する。古い検証結果は今回の成功には数えない。

## 続けて実装する範囲

- 会話側から作業へ、明示ラベルの報告言語・コードコメント言語・説明の長さを渡す初期経路を2026-11-10に追加。作業投入時のconversation-id指定に限定し、同じ会話の最新の訂正・解除と原文出典を保存する。自由文の制約・人格・任意の実行指示は自動共有しない。
- 記憶は本人の発言、モデルの推測、実行して観測した結果を区別する。
- 訂正時は以前の記録を消して隠すのではなく、何が訂正されたかと有効な最新値を保持する。
- 2026-11-10に同一作業内の失敗→編集→同種の検査成功を、入力ハッシュ・step番号・最終変更と結ぶ初期経路を追加。テストの変更で通したケースは除外し、原因は推定しない。最初の実モデル試験は16手で失敗したが、現在行の診断を追加後、同じ壊れたソースを9手で修正できた。字下げ・タブの構文エラーの経験も保持する。
- プロジェクト固有の経験を無条件で他の作業へ流用しない。一般化する場合は別の課題でも効果を確かめる。
- 既知の問題だけでなく未見の類題で、記憶がある場合・ない場合を比較する。記憶が読めることと能力向上は別に測る。

記憶による判断の改善とモデルの重みの追加学習は別。追加学習や本番モデル変更を自動で行う機能は含めない。

## 2026-11-10の記憶比較

実モデルが修正・再検証した記録を同じ作業場所で読み戻し、割引合計と平均の未見課題を記憶なしと比較した。開始時のPython入力は各組で同一、既存テスト不変・外側の別入力・今回の検証を照合。
両条件で2件とも完了したが、手数は記憶あり10+14、なし9+5。記憶の取得と再検証の接続は確認できたが、品質・効率の改善は未証明。各組1回、実行順・作業場所・記憶件数も異なるため一般的な効果は断定しない。
現在の記憶は失敗した検査と編集・成功のstepを示すが、具体的な修正差分は渡していない。次は検証済みの変更前後だけを少量・出典付きで示す候補を作り、既存の記録形式と比較する。効果がなければ採用しない。
証拠はタスクoutputs/Breaktail_修正経験の比較_20261110。追加学習は行っていない。

## 2026-11-10の差分候補

`breaktail_agent_patch_memory.py`に、所有するバックアップと現在値のハッシュ・元のテスト不変を照合し、16行・1000文字以内の差分だけを出典付きで作る実験用経路を追加した。通常の記憶へは未接続。バックアップは作業開始時の値であり、失敗検査直前の値とは区別する。原因の断定や今回の検証の省略には使わない。
同じ作業場所・入力・固定した記憶1件で差分の有無を比較した。加重平均は従来15手/差分5手、正の値の合計は差分11手/従来7手。全4件は既存テストと独立入力を通過したが、改善が一貫しないため既定採用は見送る。各課題1組で、順序・初回読み込み・前の課題の影響も残る。
部分置換で字下げを壊す失敗が差分ありでも再発した。記憶の文面調整だけを続けず、次はPythonの部分置換を保存する前の構文プレビューをP0として検討・検証する。証拠はタスクoutputs/Breaktail_修正差分の記憶候補_20261110。
