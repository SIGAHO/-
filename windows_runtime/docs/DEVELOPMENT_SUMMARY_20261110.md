# Breaktail 開発変更の総まとめ

更新日：2026-11-10（日本時間）。実装と検証の対象は `current/`。既定モデルは従来の `qwen2.5:14b`。

## 現在できること

- CLI/Webで会話し、同じ会話の原文・訂正・明示した未完了メモを参照する。
- 会話ごとに「あたし」人格を指定する。
- 指定した作業フォルダー内でファイルを調べ、編集し、Python構文検査と、明示許可した場合のテストを行う。
- 利用者の完了条件・工程依存関係を実ファイルで照合する。
- 作業を保存し、明示的な中断再開・取消・時間制限・キューへの投入と1件実行を行う。
- 同じプロジェクトの作業経験を参照する。今回の成功は今回の入力と実行結果で確認する。
- 作業場所内の制限付き文字列検索、今回の変更の読取り差分表示、WindowsのRAM等の読取り観測を行う。

**自然なヤンデレ会話の品質は未合格。完全な自律エージェントの完成、記憶による一般的な知能・効率向上は未証明。**

## 1. 原文と訂正を利用する記憶

追加：`current/breaktail_memory_hub.py`、`test_breaktail_memory_hub.py`。

FIO紹介資料の、原文を読み返す・未確認を残す・訂正を次へ持ち越すという考え方を既存保存形式に接続した。FIO本体への接続や学習の導入を意味しない。

- 同一会話の保存済みRawから関連する本人発言を読み、出典ID・時刻付きで会話入力へ渡す。
- AIの返答・提案、未コミットのデータ、別会話は自動共有しない。
- `未確認：項目｜内容`、`未完了：項目` を保持し、同名の `確認済み`・`完了`・`取消` で閉じる。
- 状態の質問と新しい申告を区別し、訂正の新しい値を優先する。
- 読取り量・引用量・入力容量を制限し、採用出典や除外理由をTraceへ残す。
- `BREAKTAIL_RAW_HUB=0` で追加参照を停止できる。

実会話17往復と、同じ履歴から機能を無効化した比較1応答を確認した。古い訂正の参照は確認できたが、複数質問の回答漏れ・不要な推測などが残る。

詳細： [FIO_MEMORY_HUB_20261109.md](FIO_MEMORY_HUB_20261109.md)、[MEMORY_DESIGN_20261109.md](MEMORY_DESIGN_20261109.md)。

## 2. 会話・人格・待ち時間

追加：`current/breaktail_character.py`、`start_atashi.ps1`、対応テスト。
変更：会話状態、返答契約、レビュー、会話生成、CLI/Web。

- 会話ごとに `/persona atashi`・`/persona off` を保存する。一人称「あたし」の参考例を必要な範囲で渡す。
- 例文を本当の思い出として扱わず、現在の依頼・会話履歴・明示した口調指定を優先する。
- ごく短い人格雑談では、永続的な事実がない場合に記憶抽出と不要なレビューを省略する。
- 起動用PowerShellの日本語文字列がWindows PowerShellで壊れる問題をUTF-8 BOMで修正した。
- 確認質問を新しい事実として上書きしない。同行者・曜日・集合場所/時刻などの明示訂正を扱う。
- 引用やコードを口調変換から保護し、レビューの指摘には実際の引用・確認できる表現を必要にする。
- 会話から勝手に外部連絡・PC操作ができると主張しない。

原文記憶の成功や一人称の統一だけで人格の合格とは扱わない。一般的な励ましに寄る、問い返しの対象を取り違える、未来の予定を完了済みとして話す、初回読込みが遅い等の課題を保持している。

詳細： [ATASHI_PERSONA_20261109.md](ATASHI_PERSONA_20261109.md)。

## 4. ファイル作業エージェント

中心：`current/breaktail_agent.py`。会話人格とは別の明示した作業ループ。

モデルの道具選択 → 引数検証 → 実行 → 観測 → 修正 → 再検証の反復を、既存CapabilityRegistryへ接続した。

利用可能な主な道具：

- `list_files`、`read_file`、`write_file`、`replace_text`
- `search_text`、`review_changes`、`observe_resources`
- `check_python`、明示許可時の `run_tests`
- 要件付きの `set_plan`、`complete_step`、実物照合後の `finish`

道具・引数は許可した形式だけを受理し、未知の道具や余分な引数を副作用の前に拒否する。
作業場所外・保護領域・リンク/ジャンクション・Breaktail自身の稼働領域を対象外とする。既存ファイルは読取り済みハッシュを必要とし、外部変更後は読み直す。変更前バックアップと変更後の読取り結果を保存する。

正常なPythonを部分置換で構文不正にする場合、保存前に拒否し候補を返す。元から構文不正なファイルの修正や全文書込みは区別する。診断には現在の該当行・字下げ・入力ハッシュを含め、同じ構文検査の無変更反復は3回で `stalled` にする。

## 5. 目標・計画・完了条件

追加：`breaktail_agent_requirements.py`、`breaktail_agent_plan.py` と対応テスト。

- 利用者が渡した目標・制約・完了条件を保存する。
- ファイルの存在、文字列、JSONの値、固定ファイルSHA-256を実ファイルと照合する。
- 必須計画では最大12工程、依存関係と完了条件の割当てを持つ。完了済み工程は勝手に作り替えない。
- `finish` の発言だけでは完了にしない。工程と現在の検証を照合する。
- 固定テストのハッシュ条件を使い、テストを弱めて通した結果だけでは成功にできないことを制御試験で確認した。

自然文の条件をすべて自動で形式化する機能、テスト品質そのものの判定は未実装。

## 6. 中断再開・取消・キュー

追加：`breaktail_agent_resume.py`、`breaktail_agent_control.py`、`breaktail_agent_queue.py` と対応テスト。

- 保存済み未完了runから、元の依頼・モデル・完了条件を保持して明示再開する。
- 同じ親runの二重再開、バックアップ/現在ファイルの不整合を拒否する。
- 過去の読取り済み状態・検証成功・テスト実行許可を自動継承しない。
- 協調的取消、手数上限、1回の時間予算を持つ。取消や期限後に保留中の次の書込みへ進まない。
- SQLiteキュー、重複投入防止、1件だけ実行するworker、OSロックによる二重worker防止を接続した。
- 前のworkerの不確かな終了は `interrupted` とし、自動で同じ操作を繰り返さない。

強制終了からの完全自動復旧、キュー外再開結果との自動同期、自動ロールバック、Breaktail自身の常駐予約・通知は未実装。

追加：`breaktail_agent_memory.py`、`breaktail_agent_preferences.py`、`breaktail_agent_lessons.py`。

- 同じプロジェクトの最近の記録から関連する経験を最大3件参照する。
- 前回結果と現在のファイルの一致をハッシュで示す。過去のテスト成功は今回の成功に数えない。
- 同一runの失敗 → 編集 → 同種検査の成功をstepと入力ハッシュで結ぶ。原因を断定せず、テストを書き換えた成功と区別する。
- `--conversation-id` を明示した時だけ、同じ会話のラベル付き書式設定3項目を作業へ渡す。報告言語・コメント言語・説明の長さに限定し、許可や任意の指示を持ち込まない。
- 実験用 `breaktail_agent_patch_memory.py` は、検証済み小差分候補を作るが、通常経路には未接続。

未見2課題の比較は両条件とも完成したが、記憶あり24手/なし14手だった。差分候補の比較も15→5手と7→11手で効果が混在した。したがって一般的な効率向上は未証明、差分候補は既定採用しない。

## 8. 検証・観測・検索・差分

### 検証対象の現在値

構文/テストの前後と完了時にPython入力の一覧とハッシュを照合する。テスト終了コード0でも入力が変化した場合は再検査を必要とする。Python以外の依存関係や一時的な変更まで保証するものではない。

### 実資源の読取り

`breaktail_agent_resources.py`：CPU論理数、Windows APIによるRAM、作業場所の空き容量を取得元・観測時刻付きで返す。失敗は未取得とし、GPUは未接続。CPU/GPU使用率や常駐監視・自動停止はない。

### 制限付き検索

`breaktail_agent_search.py`：作業場所内のUTF-8を大小区別のリテラルで検索する。パス・行・列・短い引用・ハッシュを返し、検索だけで編集を許可しない。
最大2000項目・200ファイル・読取り200万バイト・40一致行、1ファイル64KB。隠し名・保護領域・リンク・巨大/バイナリ/非UTF-8等を除外し、省略情報を表示する。

### 今回の変更の差分

`breaktail_agent_diff.py`：今回runで追跡した変更前バックアップと現在値を照合し、新規/変更/元へ復帰/外部変更/欠損/バックアップ不整合を区別する。最大20ファイル、差分合計12000文字。改行形式・BOMと表示省略を明示する。読取り専用で、検証成功フラグを付けず、復元や削除は行わない。
差分道具は実ファイルを使う制御試験と全体テストを検証済み。利用者の会話を優先し、この追加分の実モデル課題は未実施。

## 10. 起動と利用

会話：`current/start_atashi.ps1`。終了 `/exit`、人格解除 `/persona off`。

```powershell
python current/breaktail_orchestrator.py agent --workspace C:\work\my-project --text "不具合を調べて直して"
```

Pythonテストを実行させる時は `--allow-execution` を明示する。

## 11. 未実装・未接続・扱いの境界

- 自然な人格会話、自由文の長期記憶索引・制約共有、一般的な経験による能力向上は未完了。
- 汎用の任意シェル、依存インストール、JavaScript等のビルド、OSサンドボックス、完全自動復旧は未接続。
- Breaktail自身のブラウザー/GUI、外部メール/予定/MCP、専門AI協調、音声・映像、CAD/KiCad、製造機器は、今回の実装完了としていない。
- Codex側の30分ごとの開発継続と、Breaktail自身のスケジューラーは別。
- テストコードは利用者権限で動く。作業場所のパス制限はOS隔離ではない。
- 既定モデルの切替・追加学習・削除・本番サービス/会話の停止再起動・課金・実機動作は、この変更では行っていない。
- このGitHub向け変更には会話Raw、DB、認証情報、モデル重み、元のFIO PDF、ローカル評価の生ログを含めない。開発用ソース、回帰テスト、説明を対象にする。
