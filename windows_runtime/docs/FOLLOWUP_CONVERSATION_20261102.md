前回の10項目チェックだけでは、会話上の希望や自然な言い換えの取りこぼしを十分検出できなかった。固定入力を回すだけでなく、返答を読み、訂正・追加条件・別の題材を続けて送る対話で再現と修正を繰り返した。

## 原因と実装

- **検査位置**: 一度の書き直し後は無検査だった。grounding・後処理後の最終返答を検査し、必要なら最大3回修復して毎回再検査する。失敗した案はTraceへ隔離し、成功として配信しない。
- **同じ失敗の模倣**: 不合格文と過去のassistant文を再生成へ渡すと、同じ質問や助言を繰り返した。修復時はユーザー発言と出所付き状態から文脈を組み直す。
- **文数**: 句点を消費する正規表現の誤りを修正。引用内の句点は文数に数えず、構造化生成では一文ずつ配列へ格納する。句点の重複も防止する。
- **助言・質問**: 不要な助言、勧誘、許可、禁止、質問を検査する。独立した不要文だけは完全文単位で除去する。唯一の文、コード・引用・創作、数値のある実質的回答はこの除去の対象にしない。
- **前向きな締めくくりの禁止**: 「将来は良くなる」という保証だけの検査では、願いや祈りの形を見逃した。「前向きなまとめ不要」を別の継続設定として保持し、頼まれていない願いの締め文も検出する。独立した一文だけを除去し、引用や実質的な回答を切断しない。今回だけ励ましてほしいという明示指定は区別する。
- **口調**: 一人称と既知の丁寧形を、コードと引用を保護して統一する。ユーザーが示した軽い返しの参考例も保持する。
- **自己紹介の回答欠落**: 性格を聞かれた時に相槌だけで終わる返答を、既存の発話方針（率直に答える、分からないことはそのまま言う）の説明へ接地する。ユーザー自身の性格や演技中の人物像を、この説明で置き換えない。
- **出来事の時点**: 今日の話を昨日へすり替える返答を検出する。「さっきの話」は共有する話題のユーザー発言も確認し、時点が一つに定まる場合だけ保持する。複数の日が出る曖昧な文や創作には一つの日を押し付けない。
- **制約の有効範囲**: 「今回だけ質問を一つ」「今回だけ助言して」と、次の返答からの継続設定を区別する。
- **再生成を尽くした時の復旧**: ユーザーが明示した感情の受け止めか、口調への指示の了承に限り、根拠のある短文を構成して再検査する。他人の感情、引用、否定、仮定、質問を本人の確定感情へ変換しない。「短く返すほうが嬉しい」という返答の希望も、出来事の感情とは区別する。根拠のない一般的な励ましは生成しない。笑いの記号だけで内容のない返答も検出して修復する。
- **明示された短い共感**: 解決策不要・一言だけと明示して感情を話した時は、この根拠付きの受け止めを直接使う。モデルが文法上は正しいからかいや、ユーザーにない感情を足した文を通さない。通常の雑談や創作全般を固定の台詞へ置き換える処理ではない。
- **依頼された質問**: 情報を尋ねるだけの質問と、疑問形の助言を審査で区別する。話題指定なしで質問を一つ明示的に求められた場合も、再生成を尽くした時は一つの普通の質問へ復旧できる。指定された話題を無視する汎用質問への置換はしない。復旧文は固定した文法とユーザーの明示根拠から構成し、構造・口調・制約を再検査する。モデルが自由生成した案とは区別してTraceへ証拠とともに記録する。
- **日本語漏れ**: 指示のない英語・中国語の断片は再生成へ戻す。ユーザーが提示した固有文字や、明示された翻訳・外国語の依頼は区別し、文字だけを勝手に削らない。
- **意味・日本語の独立審査**: 表現の一覧だけでは「方法と利点」の説明に紛れた助言を見逃した。同じローカルモデルへ最終返答だけを渡し、助言・未来の保証・明白な日本語の破綻を別呼出しで分類する。違反は返答中に実在する逐語引用を必須とし、不正な引用・不正JSON・通信失敗は合格にしない。通常の共感や冗談と、行動への誘い・許可を区別する。検算済みの数値・論理はこのモデルの判断で変更しない。
- **創作**: 要素が名前だけ登場しても、指定された行動を実行していなければ不合格にする。一方、「猫が会議を止めた」のような正しい活用は認め、語句の丸暗記にしない。
- **予定**: 要約と変更点だけの返答は、ユーザー由来の状態から組み立てる。複数項目の要約で残金が消える経路も修正。混雑回避の簡単な案は確定した目的地と費用から構成し、明示的な未承認候補として提示する。
- **複数項目の想起**: 呼び名・同行者・続柄・苦手・最初の購入品を一緒に確認された時は、出所のある保存値を組み立てる。項目を捨てず、分からない項目だけを不明とする。回答の末尾で「他は全て不明」と根拠なく付け足さない。
- **計算**: 「足りる」「以内」といった聞き方も検算へ回す。入場料を含む条件を後続の訂正でも維持し、晴天条件へ戻す時は区別する。既に正しかった直前の返答を、ユーザーに合わせて誤りだったと説明しない。

初回生成は既定temperature 0.4。短い返答は初回上限512トークンとし、修復時は0.35〜0.55で再生成する。モデルは同じローカルOllama qwen2.5:14b BASE。CLIの既定5往復履歴と8192コンテキストを保ち、各往復でプロセスを再起動して状態を復元する。

意味審査はtemperature 0、最大256トークンで同じモデルを使う。短い返答でも追加呼出しが必要な場合がある。モデル審査は任意の内容の正しさを保証するものではなく、ここで再現した助言・日本語の失敗を検出するための追加経路である。

既存ユニットテストでは新たな外部モデル審査を依存先として分離する。審査の形式・引用・障害時の扱い・不合格から再生成して再検査する流れは専用テストで検証する。実会話評価では生成も審査も実際のOllamaを使い、テストの代役は使わない。
