# 修正方針と実装状況

1. **後処理・grounding: 実装済み。** 定型末尾を文単位で削除し、文の途中では削らない。メモ帳起動・自発通知の回答を合成し、関係ない回答を維持する。コード作成依頼を能力質問と混同しない。
2. **検算・有限論理: 実装済み。** ASTの許可演算だけをFractionで評価する。金額の明示式と、人数・交通費・昼食・条件付き入場料を検算する。箱ごとの真の文の個数を列挙し、説明修正でも元条件を維持する。
3. **会話状態: 対応する明示パターンを実装済み。** 本人・同行者・続柄・曜日・予算・交通費・食費・入場料・苦手・購入品をユーザー発言だけから保持。各値には出所・ターン・状態を付ける。モデル発言を登録しない。
4. **発話制約: 改善済み、残課題あり。** 明示希望をセッション内に保持し、検出した違反は一回だけ再生成。残る違反はTraceに記録し、意味内容を無条件に切り捨てない。
5. **回帰・実測: 実施済み。** 20往復の合成回帰ケースと、元の20入力の別領域でのOllama実測を分けて実施する。

## 次に必要な改善

- 任意の人物表現・条件付き費用・提案承認を扱う汎用の状態モデルと曖昧性処理。
- 検算対象の範囲を、単位・人数・条件・発言者を含む型で拡張する。
- 一般的な出力反復の検出と復旧。今回の診断実行で反復を一度観測した。
- 固定人格、短さ、共感、創作の意味を人手で評価し続ける。通信成功を意味成功に数えない。
- Web/Studioや既存のユーザー記憶がある本番セッションでの追加評価。
